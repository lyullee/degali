# 부력을 함께 맞추는 독립 엔탈피 폭 — 2026-09-05

## 결과와 적용 범위

**다섯 플럭스와 단면 부력을 함께 맞추는 새 경계 후보가 일곱 시험 모두 통과했다.**
직전 동일 폭 후보의 부력 불일치를 줄이기 위해 열 폭 자유도 하나를 추가했다.
동시에 중심 온도와 수소 분포 폭의 기존 기준도 충족한다.

이는 근접장과 하류 사이의 **경계 표현 개선**이다. 하류 수송식이나 전체
현장 오차 검증이 끝난 것이 아니다. 기본 DEGADIS 경로는 바꾸지 않았고,
기존 후보의 온도 오차 약 5% 개선 수치를 이 새 후보에 적용하지 않는다.
이번에는 농도/온도 관측을 맞추거나 전체 38/17 현장 점수를 계산하지 않았다.

## 바꾼 수식

[계산 전 고정한 계획](prereg-buoyancy-constrained-enthalpy-width.md)에 따라:

```
C = rho*Y = C_c*G
H = rho*(h-h_a) = H_c*G^(1/beta_H^2)
u = u_a*cos(theta) + u_c*G^(1.16^2)
F_b = g * integral(rho_a-rho) dA
```

beta_H는 엔탈피 분포 폭 / 수소 질량밀도 분포 폭이다. H와 C는 각각 체적당
엔탈피와 수소 질량이며, 온도나 질량분율 자체를 가우스로 가정한 것이 아니다.
국소 rho,Y,T는 기존 주변 일관성 상평형 표로 구한다.

여섯 미지수에 질량/H2/수평·수직 운동량/총에너지 및 F_b의 여섯 제약을 적용했다.
운동량 방향과 H2 유량을 먼저 제거해 네 미지수로 푼다. beta_H는 관측값이 아닌
**동일 근접장 모델의 목표 플럭스와 부력**으로 결정된다. 기존 1.16 속도 폭비,
소스, 주변 조건, 접속 위치, 유입 계수와 중력은 유지했다.

F_b의 단위는 N/m이며, 유속을 곱한 부력 플럭스와 다르다. 부력은 하류에서
상수로 보존할 양이 아니다. 경계 제약을 하류 보존식으로 잘못 옮기지 않았다.

## 수치 검증

- 최대 다섯 플럭스 상대 잔차: 2.952e-11 (기준 1e-8).
- 최대 부력 일치 잔차: 7.050e-14. 척도는 `max(abs(F_target), 1e-3 N/m)`.
- 재맞춤한 상태에서의 적분 차수 변화: 다섯 플럭스 최대 8.353e-7,
  부력 최대 5.574e-6 (둘 다 기준 1e-5).
- 최종 적분 차수는 시험별 512–2048. 에너지만 수렴했을 때 승인하지 않는다.
- 새 환경에서 기존 저장 단면의 다섯 플럭스와 부력을 먼저 재생했다.
  최대 척도 오차는 1.776e-15였다.

별도로 Gauss–Kronrod 21점 적응 적분으로 같은 고정 단면을 다시 계산했다.
원래 두 구간으로 변환한 Gauss–Legendre 절점과 다른 절점/세분화 방법을 쓰며,
직접 q 좌표에서 정사각형의 각도 가중치를 적분한다. 여섯 양의 최대 척도 차이는
2.760e-6으로, 일곱 조건 모두 1e-5 기준을 통과했다. 원래 근접장 목표의
정확도나 하류 수송을 이 감사로 검증한 것은 아니다.

처음의 점별 적분 실행은 두 조건을 검사한 후 속도 개선을 위해 중단했고,
결과 JSON은 저장하지 않았다. 같은 GK21 식을 배열로 처리하는
[SciPy cubature](https://docs.scipy.org/doc/scipy/reference/generated/scipy.integrate.cubature.html)로
일곱 조건 모두 다시 실행했다. 정규화된 각 성분의 적분 오차 요구는 1e-8이며,
물리 가정이나 승인 기준을 완화하지 않았다. 최종 감사 파일은
`buoyancy_constrained_enthalpy_width_independent_audit_2026-09-05.json`이다.

상평형 역산을 유한 차분으로만 반복하면 여섯 제약을 맞추는 과정이 불안정했다.
기존 표의 H(rho,C) 미분과 암시적 밀도 미분을 연결하고, 미지수 민감도에 따른
수치 스케일링을 적용했다. 먼저 고정 열 폭에서 다섯 플럭스를 맞춘 초기값을
사용한다. 이것은 수치 해법의 보완이며 물리 계수나 허용오차 변경이 아니다.

합성 경계 복원과 독립 유한차분 미분 검사를 통과했다. 보간표 절점에서 양쪽
기울기가 다르다는 점을 구분했고, 거의 중성 부력인 합성 조건에서는 다섯 플럭스가
잘 맞아도 부력 적분이 미수렴하면 거부하는 시험을 유지했다.

최종 일반 회귀는 **225 passed, 128 skipped, 58 deselected** (153.47초).
그중 새 경계 시험은 17개다. 건너뛴 시험을 통과로 세지 않았고, Linux gfortran
전체 오라클 회귀는 이번 Windows 실행으로 완료하지 않았다.

## 아직 남은 하류 수송

경계 beta_H가 구해졌다고 하류에서 고정시켜도 된다는 뜻은 아니다.
열 폭까지 포함하면 기존 다섯 플럭스와 두 위치식만으로는 미분식이 한 개 부족하다.
현재 클래스는 `solve`, 미분/소스 계산과 센서 예측을 명시적으로 거부한다.

다음 구현 대상은 [독립 열 폭 수송 명세](thermal-width-transport-requirements.md)에
정리했다. 엔탈피의 2차 단면 모멘트는 가능한 추가 상태이나, 횡방향 열 플럭스,
곡선 좌표·단면 경계 항, 운동에너지/TKE 교환을 먼저 정해야 한다.
`d beta_H/ds=0`이나 `dF_b/ds=0`을 임의로 추가하지 않는다.

## 실행 환경과 재현

앱 실행 환경 갱신 후 SciPy/CoolProp/pytest가 없어 프로젝트의 `.venv`에 복구했다.
과학 계산 패키지는 `.venv`의 로컬 설치를 사용한다. 실제 버전은 Python 3.12.14,
NumPy 2.3.5, SciPy 1.18.1, CoolProp 8.0.0, pytest 9.1.1이며,
`requirements-research.txt`에 고정했다. 입력/코드/환경 버전은 결과에도 기록했다.
기본 문서 처리 패키지는 기반 실행 환경을 참조하는 가상환경 설정이다.

```
.venv\Scripts\python.exe tools/run_buoyancy_width_screen.py --output <새 경계 JSON>
.venv\Scripts\python.exe tools/audit_buoyancy_width_boundary.py <경계 JSON> <새 독립 감사 JSON>
.venv\Scripts\python.exe -m pytest -m "not slow" -q
```

경계 결과는 `reference/preslhy/buoyancy_constrained_enthalpy_width_interface_2026-09-05.json`.
원본과 이전 결과는 덮어쓰지 않았다. 새 클래스는
`src/degali/addons/buoyancy_profile.py`에 있으며 일반 하류 선택지로 노출하지 않았다.
